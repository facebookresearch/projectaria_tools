# Changelog

---
## Version 1.5.0
- Get help from the MPS CLI: press `R`, or **Get help** on the banner that appears when a recording fails processing, to send a debug report (logs and machine details) to Meta
- Optionally share the failed recordings with a report. MPS processes them again and Meta keeps a decrypted copy if they fail again; a failed or interrupted share is retried on later runs under the same account, 3 tries in all within 30 days
- Report from `--no-ui` runs: the CLI asks before sending when a run fails or is interrupted, and the new `--report-on-failure` option sends the report without asking, for unattended runs
- Keep log output from native libraries (VRS reader, video decoder, VRS Health Check) off the status table; it goes to the session log instead
- Redact credentials from logs and error messages
- Upload the Eye Gaze calibration only when a recording is eligible for Eye Gaze, and show calibration upload and link status separately
- Run the VRS Health Check through its Python API, so it no longer depends on the `run_vrs_health_check` command being on `PATH`
- Encrypt and upload VRS files larger than 64 GiB, which previously failed to encrypt
- Check the status of active requests in batched queries, with a 30-second timeout and one retry budget shared across failures


---
## Version 1.4.0
- Add Eye Gaze processing for Aria Gen 2 recordings
- Add the optional single-mode `--calib` input for personalized Eye Gaze results
- Upload each calibration once per run, link it only to requests that submit Eye Gaze, and show upload and link status without internal recording IDs
- Warn when a calibration file is not marked as such, and do not upload it when Eye Gaze is not requested
- Submit a fresh Eye Gaze request instead of reusing a prior server request, so it does not inherit an unknown calibration state; `--retry-failed` therefore has no effect on Eye Gaze
- Validate downloaded MPS results before extraction, retry incomplete transfers, and report actionable errors for invalid results (`120`), calibration upload failures (`121`), and missing Gen 2 eye tracking streams (`122`)
- Keep encrypted calibration uploads beside the calibration VRS instead of creating a result-style output folder

## Version 1.3.0
- Integrate the unified login surface — projectaria-login — into the MPS CLI. When the system keyring is unavailable (headless servers, containers, CI), the auth token is now saved to an encrypted local file instead of not being saved at all
- Always re-run the VRS health check instead of reusing an existing vrs_health_check.json, so results never come from an older VRS Health Check version
- Update projectaria-vrs-health-check to v1.3.0
- Update aiohttp to 3.14.3
